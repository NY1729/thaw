# tools/parity: differential surface and behaviour harness (thaw-js vs Node)

Node is the oracle. `thaw-js-node` (a plain bin, no thaw-cli build) is the subject.
Each corpus runs on both; outputs are normalised and diffed per probe name.
Plan: `designs/plan-q9-systematic-parity.md` sections 0, 3 (H1), 6 (item 1-2).

## Layout

- `surface.js`: own names + descriptor shape (typeof, flags, length/name for functions, toStringTag) for globals, process and key builtin prototypes. Descriptors only, no getter is invoked.
- `corpus/*.js`: behaviour probes, `t(name, fn)` one line each. A throw is reported as `THROW <ErrorName>: <message>`, never a crash.
  - `invariants.js` strict-mode mutation violations and sloppy counterparts
  - `tags.js` `Object.prototype.toString` tags and `Symbol.toStringTag` values
  - `timers.js` Timeout/Immediate/Interval members, ref/unref/refresh, toPrimitive/dispose
  - `process.js` process member typeof and value shapes (no exit/kill/chdir/setuid)
  - `iterators.js` shared %IteratorPrototype% and Map/Set/Array/String iterator protos
  - `errors.js` captureStackTrace, prepareStackTrace, stack, cause, AggregateError
  - `names_lengths.js` name/length of builtins and global functions, function own props
  - `structured_clone.js` structuredClone per value family
- `seed/`: the original probes (sib.js, surf2.js), kept as reference only.
- `run.sh`: runs every corpus on node and on the runner, then `diff.py`.
- `diff.py`: normalise, diff, print a table, write gaps.json, gate against a baseline.
- `selftest.sh`: proves the gates on synthetic outputs, plus the builtin table generator and staleness check.
- `known-gaps.json`: recorded baseline. Gaps may only shrink.
- `waivers.json`: user-approved classification of known gaps as waived (see Waivers).
- `skip.txt`: probe-name regexes dropped from both sides (bare-runner limits, not gaps).

## Run

    tools/parity/selftest.sh
    tools/parity/run.sh [OUT_DIR]               # gate: exit 1 only on gaps not in known-gaps.json
    tools/parity/run.sh --write-baseline [OUT]  # record current gaps (only after a fix lands)

Env: `THAW_JS_NODE` (runner, built with `--features intl,wasm`; default `<repo>/target/release/thaw-js-node`, falling back to the ra8 prebuilt `/home/fedora/work/thaw-tmp/ra8/target/release/thaw-js-node` if that does not exist), `NODE` (oracle, default `node`), `PARITY_TIMEOUT` (seconds per thaw corpus, default 60), `PARITY_SCRATCH` (scratch base dir, created if missing; default `$RUNNER_TEMP`, then `$TMPDIR`, then `/home/fedora/work/thaw-tmp/parity-scratch`). Default OUT is `$PARITY_SCRATCH/out`; `selftest.sh` makes a fresh `mktemp -d` under the same base (or uses `PARITY_SELFTEST_DIR` if set). Nothing is written into the repo except `known-gaps.json` on `--write-baseline`.

## Output and exit codes

- Table per corpus: probes compared, MISSING, DIFFERENT, EXTRA (thaw-only, informational).
- Per gap: status (`known` / `NEW`), kind, probe id `corpus::name`, node value, thaw value.
- `gaps.json` in OUT: all gaps with both values.
- Exit 0: no new gaps. Exit 1: at least one gap not in the baseline (listed). Exit 2: harness error (oracle failed, duplicate probe name in one file).
- Fixed gaps are listed as "fixed since baseline"; they pass, and `--write-baseline` ratchets them out.

## Normalisation (diff.py)

- `THROW <Name>: <message>` compares by error name only. Messages differ by engine.
- Absolute `/home/...` paths, `0x` addresses and `<n>ms` durations are masked.
- Whitespace is collapsed. Lines without ` = ` are raw probes keyed by the whole line.

## Adding a probe

Keep expected output generated by node, never hand-written. Probe names must be unique per file (a duplicate is exit 2). Use `G('Path.To.Global')` instead of bare identifiers so a missing global is a visible gap, not a ReferenceError. Probes that need `require` go in the skip list, not the baseline. Intl and WebAssembly are measured (the runner is built with `--features intl,wasm`).

## Known limits

- The prebuilt `ra8` runner predates #556-#562 (it has #554/#555). Gaps the later PRs closed still show as gaps here. Re-run against a current runner build before reading the baseline as current.
- The runner has no `require`; probes that touch it are skipped (`skip.txt`). `run.sh` refuses a runner without Intl and WebAssembly (exit 2), so build it with `cargo build --release -p thaw-js --bin thaw-js-node --features intl,wasm`.
- `process.mainModule` is set by the real entry path (`web/main_file.js`), not by the bare runner, so its probes are skipped (`skip.txt`).
- Node-only globals such as `fetch`, `WebSocket`, `Blob` are counted as gaps when thaw lacks them; the plan's H2 routed run is the check that decides whether they are runner-only.
- The surface corpus reports `globalThis.<name>` and `<name>` separately for each global, so one missing global can appear as two gaps.

## Waivers (waivers.json)

A waiver classifies a gap as waived, so the report can separate gaps Thaw is not expected to match from real ones. It never changes the gate: exit 1 still happens only for a gap id not in `known-gaps.json`, and waived gaps stay baseline entries there.

- `waivers.json` is a list of `{id, reason, match}`. `id` is `W<n>`, unique. `match` is a list of regexes, each fullmatched against the gap id `corpus::probe`. An explicit id is a regex with no metacharacters.
- `diff.py --waivers` (run.sh passes it) writes `waived` and `waiver` into each `gaps.json` entry, and prints real and waived columns per corpus plus a count per waiver id. A gap matching two rules is counted under the first and listed in the report.
- Selftest covers the classification on synthetic ids, and checks the checked-in file: a real ES symbol such as `console.Console.[Symbol(Symbol.hasInstance)]` stays real, `kIsConsole` is W1, and `WebAssembly.Tag`, `process[kCapture]` and `EventTarget[nodejs.event_target]` stay real.

Current waivers (user-approved; `waivers.json` is the source of truth):
- W1: Node-internal symbols and `k*` private fields. `kCapture` and `nodejs.event_target` are excluded (real since 2026-11-16).
- W3: SharedArrayBuffer `maxByteLength` and `grow` only (the resizable ArrayBuffer members are implemented; PR2 removes this waiver). The `Atomics.waitAsync` waiver is withdrawn.
- W5: value differences only (ppid, groups, setuid family, usage counters). The key set and value types of `process.versions` and `process.release` must match Node, so those probes are real gaps.
- W2 (WebAssembly Tag/JSTag/Exception and streaming entry points) and W4 (all of Intl) are withdrawn. Those gaps are real.
- W6, W7, W8, W9: unchanged.

To add a waiver, get explicit user approval first and record it in the `reason`. Never add one without it. Then add the entry to `waivers.json`, run `tools/parity/selftest.sh`, and check the per-waiver counts in a run.

## node_globals.json

`node_globals.json` is Node 22's own global object, sorted, as `[name, typeof]` pairs.
`crates/thaw-hir/src/lower/platform_globals.rs` is checked against it by unit tests.

Regenerate (Node 22; the output is single-line JSON):

    node -e "console.log(JSON.stringify(Object.getOwnPropertyNames(globalThis).map(n=>[n, typeof globalThis[n]]).sort()))" > tools/parity/node_globals.json

The raw output includes CommonJS-wrapper bindings and REPL/`-e` builtin-module
names (`require`, `fs`, `util`, ...). Those are not script globals; they are
listed in `NODE_ONLY_NOT_GLOBAL` in `platform_globals.rs`. A new Node release
that adds a global fails `every_node_global_is_classified` until it is added to
`PLATFORM_GLOBALS` or documented in one of the exception lists.

## builtin_table.tsv

`crates/thaw-js/src/builtin_table.tsv` is the Node 22 descriptor table of the builtin surface: one row per own key of each global, intrinsic, and their members and `.prototype`s (depth 2). Columns: `owner`, `key` (symbols as `@@name`), `kind` (`data`|`accessor`), `flags` (`w e c` as letters or `-`; accessors have `-` for w), `vtype` (typeof; primitive values are not recorded), `length`/`name` (functions; accessors give `get x|set x`), `hasPrototype`, `alias` (same object reached by two paths shares an id), `tag` (`Symbol.toStringTag` string value on that owner). Roots come from `node_globals.json` plus `%TypedArray%`, `%IteratorPrototype%`, `%GeneratorFunction%` and similar. `process.env`, `process.versions` and similar are not walked. The output is deterministic and machine-independent.

Regenerate after a Node 22 change, or when a builtin changes shape, and commit the result:

    node tools/parity/gen_builtin_table.js crates/thaw-js/src/builtin_table.tsv

The generator refuses to run on any Node other than 22. Check that the checked-in copy is current (also run non-gating in `parity.yml`):

    tools/parity/check_builtin_table.sh          # exit 0 current, 1 drift, 2 generator/harness error

`crates/thaw-js/src/builtin_table_missing.txt` is the ratchet list of rows thaw-js does not provide yet; it is filled by the WI-1b conformance test, not by hand. Plan: `designs/plan-q9-f1-builtin-surface.md` sections 2.1 and 2.4.
