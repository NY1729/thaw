## Corrected pinned API and timing proof

`rquickjs-core 0.12.2` has `unsafe impl<'js,T: JsLifetime<'js>> JsLifetime for Module<'js,T>` (`js_lifetime.rs:184`), but its `Declared` marker (`value/module.rs:190–191`) has **no** `JsLifetime` implementation. I incorrectly claimed `Module<Declared>` directly satisfies this bound. The existing `NativeBundleOwner<'js>` in `quickjs/context.rs:197–205` instead has its own explicit `unsafe impl JsLifetime` and may hold a private `RefCell<HashMap<String, Module<'js, Declared>>>` under the same context lifetime discipline. The engine module cache owns module definitions; the record's `Ctx` and userdata cannot outlive that runtime, and `Opaque::clear` drops userdata before `JS_FreeRuntime`. This is a source-backed *manual owner obligation*, not an upstream trait guarantee. A candidate must review that unsafe lifetime invariant explicitly; if it cannot, native terminal read is HOLD.

Do **not** call `Module::namespace()` in `BundleModuleLoader::load`: that module is only declared. Pinned QuickJS `js_build_module_ns` (`quickjs.c:30375–30494`) resolves exports and dereferences module var refs/function object; before linking those may not exist. Pinned `JS_EvalFunctionInternal` (`quickjs.c:37273–37283`) calls `js_create_module_function` then `js_link_module` before `js_evaluate_module`. The loader may store the declared handle after `Module::declare`; the entry path stores its own cloned handle before `eval`. A private native-terminal read made during module evaluation can then clone that handle, drop all userdata/RefCell guards, call `namespace()` and read the property. At that point the graph is linked, so QuickJS's var/function/lexical cell and TDZ behavior is preserved. Reject any private read before linking or for a missing registered module instead of trying to construct a namespace from a bare declaration. Record the original JS exception from `Object::get`; do not substitute `undefined`.

## Minimal staged implementation

1. **Private read precursor, mixed gate still off.** Extend unit312's context owner with declared handles, record them in both `BundleModuleLoader::load` and entry declaration, and expose a *lexically held capability* alongside the bound entry evaluator, not a public `eval(token)` or mutable registry global. Keep the Rust-minted sequence and existing nonbundle-absolute resolver rejection. Return a native terminal's value only after linked-state evidence; never route it through `__thaw_bundle_require`. Source-only unrun controls: function/var cycle, lexical TDZ, missing property, failed link, repeated read and reentry. The private capability must release userdata guards before any engine call. This stage alone is a precursor and does not enable mixed collection.

2. **Use the existing origin object as the facade.** `STAR_ORIGIN_RUNTIME` in `bundle/render.rs:22–205` already implements explicit-over-star, ambiguity/diamond identity, opaque edge publication/version retry, and `track(exports)` which waits for `linksReady`, materializes the names once, then installs getters. Its `cjs` read (`render.rs:106–113`) already does a fresh `value[name]` on each access. Change only its `esm` terminal read (`render.rs:115–116`) to the private native capability and keep CJS/default edge logic. Reuse this materialized `exports` object for named/default/namespace/`export * as ns`/mixed dynamic-import consumers. Do **not** add a late-key Proxy, `ownKeys` traps or custom object-integrity policy: the baseline contract fixes the key set when `track` links, while getters remain live afterward. An ordinary user object with a later-added CJS key was not promised dynamic namespace-key discovery by the existing renderer. The bridge and mixed entry must expose the chosen tracked facade, not a raw native namespace.

3. **Mixed source-order gate.** Preserve native static import order with an opaque dependency adapter that invokes the *captured per-bundle* `__thaw_bundle_require` at the dependency's evaluation point, publishes the same `origin.edge`, and uses the existing import-condition map. A no-op `export {}` shell is insufficient. The existing scope-aware visitor (`module_transform.rs:615–955`) must rewrite import references whose origin may be opaque to `origin.read` without eager value capture, preserving lexical shadowing, shorthand, detached named calls, optional calls and tags. Pure native imports stay native. For opaque-origin reexports, no native `export const` snapshot is allowed; bundled readers use the materialized origin facade. If this adapter and visitor cannot be reviewed as one coherent source-order path, leave `collection.rs`'s mixed native gate false and accept only stage 1.

4. **Remaining enablement gates.** CJS-first synchronous `require` of ESM still needs same registered module evaluation, immediate settled-Promise inspection, TLA rejection, original throw and rollback; current `render.rs:344–369` cannot do this. Worker source (`render.rs:412–420`, `bundle/workers.rs`) still snapshots/rewrite-to-CJS and needs child-context originating bundle registration before native mixed routing. Until those are implemented, exclude CJS→ESM require and Worker-bearing graphs from the mixed native gate. Nonliteral dynamic imports remain legacy as the collector already records them. The full historical mixed finding stays open through precursors.

The next code candidate should be **stage 1 only**, with exact old/new owner hashes and no mixed-route enablement. Stage 2/3 needs its own source-plan approval after the private read implementation is reviewed, because the opaque adapter's order and private capability delivery are load-bearing.
