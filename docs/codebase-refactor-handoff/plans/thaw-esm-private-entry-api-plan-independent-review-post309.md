# Independent source review: native ESM private entry plans

Reviewed immutable `/tmp/thaw-esm-private-entry-api-plan-post307.md` (SHA-256 `ff24601c1fb343f9d727a04fd9aeb21f858159f5261e42ce29cd8a5f95b6db2d`) and its v2 ordering supplement `/tmp/thaw-esm-private-entry-api-plan-post307-v2.md` against current HEAD309. Source-only; no product execution or managed edits.

Verdict: **HOLD for an implementation freeze**, with the state-before-eval correction accepted in principle. `Promise::new` is backed by QuickJS `JS_NewPromiseCapability` (`rquickjs-core-0.12.2/context/ctx.rs:383-398`). `Module::declare` is compile-only (`value/module.rs:259-279`), while `Module::eval` invokes `JS_EvalFunction` (`:375-396`), so publishing a ready Promise before eval is necessary for synchronous reentry. Repeated requests can return that same Promise without redeclaring. The existing host load loop (`thaw-quickjs/src/quickjs/api.rs:315-345,634-675`) drives pending jobs, so no nested `Promise::finish` belongs in the host callback. Current resolver/loader (`context.rs:189-243`) relies on a mutable global table and permits nonbundle absolute entry imports; the proposed private userdata and nonbundle denial address that intended boundary. `Opaque::clear` drops userdata before runtime teardown (`rquickjs-core/runtime/opaque.rs:284-294`), matching the existing `NativeCallbackIdentityBridge` pattern (`context.rs:248-283`).

Required design corrections before code acceptance:

1. The v1 owner describes one `HashMap<String, Module<'js, Declared>>`; v2 then says to store `Module<'js, Evaluated>` after `eval`. These are distinct types (`rquickjs-core/value/module.rs:191-205,375-396`). Keep declared dependency modules and evaluated entry modules in appropriately typed fields or an explicit small enum; do not treat an evaluated handle as a declared one. This is a concrete Rust type gate, not an ABI change.
2. Every path after `ready` is stored must settle it. The v2 success callback obtains `evaluated.namespace()` and then resolves `ready`; `namespace()` returns `Result<Object>` (`module.rs:502-508`). If it errors or the callback itself throws, the Promise returned by `.then` rejects but the separately stored `ready` stays pending. The callback must catch that error and reject `ready` with the original JS exception (or a JS Error for nonexception Rust failures). Likewise all declare, eval, callback construction, and attach failures must reject the same ready Promise. An unrun namespace/callback-failure control should prove no `WouldBlock` from a permanently pending ready state.
3. `__thaw_eval_native_entry(token)` is a public host call. The plan calls the token “opaque” but does not specify an unforgeable representation. If it is merely the predictable `thaw-bundle:<sequence>:<main>` string, same-realm user code can guess a previous sequence and ask this API for the old raw namespace, bypassing the resolver's nonbundle gate. Use an identity capability or otherwise prove old entry tokens cannot be minted or guessed by arbitrary scripts. A source-level old-sequence probing regression belongs beside the cross-owner import test. A monotonically checked sequence alone is an owner key, not an access capability.

Additional implementation checks: the `.then` method is fetched from the eval Promise through `Promise::then()` (`value/promise.rs:91-94`), and QuickJS user scripts can modify `Promise.prototype.then`; if the host API must be robust against that, capture the intrinsic at context initialization rather than assuming a successful `.call` attached the callbacks. Callback failure handling above is mandatory in either case. Keep every userdata/RefCell guard dropped before JS entry, including namespace and reject calls. Validate module-name NUL before minting if registration promises all malformed payloads fail without retained records (`Module::declare` uses `CString::new`). These are bounded gates within the proposed private owner design; no CJS/mixed/Worker claim follows from this review.
