# Error-message control-marker collision: source design

Exact historical ID `01a0f4f7-d573-7932-b332-974a3968ad2a:0`; current HEAD314 `d5d36477b9668edd5fee53a4c6a0c4db56fa1639`. Source-only; no product execution or managed edit. The original body is specifically `Error("first\u0002second")`: the string join in HIR puts literal U+0002 in the message, while runtime `split_error_tag_bytes` and `split_error_cause` treat it as the cause boundary. The same collision occurs for U+0003–U+0006. Unit313 preserved WTF-8 bytes but intentionally did not solve this parsing ambiguity.

## Producer inventory and minimal wire

The common legacy shape is `SOH name SOH message [name-override][cause][code][props][suppressed]`. Preserve that prefix, class ancestry payload, and the existing optional suffixes, but frame the *message segment* for newly generated structured errors:

`SOH name SOH RS E1 : <UTF-16-code-unit-length> : <raw-WTF-8 message> <legacy suffixes>`.

`RS E1:` is a version discriminator after the second SOH; the decimal length, not the first marker in the message, determines the suffix start. UTF-16 units match JS `String.length`/`slice` and include lone surrogates as one unit and astral characters as two. The native decoder must scan WTF-8 to find the byte boundary without converting the message to well-formed UTF-8, reusing its existing UTF-16/WTF-8 codec rules and `NativeStr` length metadata. A malformed frame should fall back to the legacy parse, not silently drop the body. For nonlegacy new frames, cause/code/name-override/props/suppressed parsing begins only at the computed suffix start. This is a bounded message-framing change, not an Error-object ABI replacement or a general replacement of every optional field's delimiter grammar. A valid old unframed message deliberately beginning with the exact version header is inherently ambiguous without an out-of-band tag; legacy fallback is best-effort, while all new producers use the frame.

Producers that interpolate user-controlled message text and must adopt one shared framing operation:

- HIR `expressions/lowering.rs:3787–3852` `new Error` family and `invocations/calls.rs:1505–1560` callable Error family both currently concatenate a static `SOH name SOH` prefix, then message, then optional cause. Replace the first concatenation with a runtime `__thaw_error_frame(name,message)` intrinsic; preserve evaluation order and append the existing cause suffix *after* the framed body. The compiler-generated typed-error literals at `expressions/lowering.rs:129`, `objects.rs`, `assignments/lowering.rs`, and LLVM `compile_throw_builtin_error`/other fixed messages have no user-controlled control bytes and may remain legacy. If a generated message interpolates user text (for example a property name), it must use the same frame rather than be assumed fixed.
- HIR `expressions/coercions.rs:910–975` turns a thrown Error-subclass object into `SOH ancestry SOH message SOH4 runtimeName`; frame the `message` before appending the name override. `statements/narrowing.rs:283–290` calls `thaw_error_suppress`; that runtime constructor must frame its own supplied message before its length-prefixed nested errors.
- QuickJS `api.rs:2628–2745` `describe_tagged_exception`, `describe_host_exception`, and `describe_promise_exception` interpolate `error.message`/rejection reason and sometimes append code/property metadata. Use the same framing rule through a small shared Rust encoder. Crucially migrate the plain-Error promise branch that currently adds a trailing `SOH Error SOH message` after labeled text; newly emitted structured promise errors should have a leading tag plus framed *display* message and the preserved property suffix. Ordinary `throw "string"` remains an untagged value, not a synthetic Error. `error_property_json` is the property-bag producer but does not itself parse the wire.
- NAPI `module_host.rs:2529–2550` `describe_env_exception` builds `SOH name SOH message` for typed native errors; frame it. The callback error path around `2944–2950` reads a tagged QuickJS error before `alloc_error` and must decode a framed body. Plain string/native-addon errors without a registered error name stay untagged.
- Other direct tagged literals across HIR, LLVM, thaw-std, and QuickJS are static diagnostics; audit each interpolated input before leaving it legacy. Their current literal `SOH` prefix remains accepted by the backwards-compatible reader.

The smallest shared implementation is a pure `encode_message_frame`/`split_message_frame` byte helper in existing `thaw-arena` (already a dependency of runtime, QuickJS, and NAPI), plus one runtime C ABI `thaw_error_frame(name,message)` wrapper for generated HIR/LLVM. This avoids new crate edges and repeated Rust formatting rules. The JS bootstrap needs only a matching tiny `String.length` frame parser, not another general error representation. Verify the shared helper's native string ownership and arena reset rules before code is frozen.

## Reader inventory

- `thaw-runtime/native_values/errors.rs`: central `split_error_tag_bytes`/`split_error_tag`, `resolved_error_name`, `split_error_name_override`, `split_error_cause`, `split_error_code`, `error_property`, `split_suppressed_error`/`split_suppressed`, `to_string`, `stack`, `is_instance`, `is_error`, and `thaw_error_message`. One parsed view should expose chain/body/suffix; every suffix reader must search **only suffix**, not raw full text. `thaw_error_suppress` both consumes nested tags and produces a combined tag. Its existing nested length fields stay intact.
- `thaw-quickjs/api.rs:302–306` `tagged_error_parts` is used by uncaught-exception and unhandled-rejection emission; it must return decoded display body. `platform_globals/runtime.js:511–535` `__thaw_error_from_tagged` reconstructs JS Error and own properties after native callback/rejection; it must slice framed message before parsing suffix. `platform_globals/dates.js:44–53` JSON reviver turns an error-tag string into an Error; it must decode the frame. Both JS readers retain the legacy branch for old wire.
- `thaw-napi/module_host.rs:2944–2950` typed callback-error reconstruction directly splits on SOH and must use the framed parser. The `result.strip_prefix(U+0002)` at 2889/2939 is the *callback result status* marker, not the Error cause suffix; do not change that framing by accident.
- LLVM `runtime_declarations.rs:1598–1635` and `invocations/calls.rs:1339–1400` only declare/route runtime readers; add the one encoder intrinsic declaration/routing without changing the existing reader symbol ABIs. Console Error display uses `thaw_error_message` centrally.

## Implementation gates and unrun controls

Before implementation, prove a shared byte parser can map UTF-16 count to WTF-8 byte boundary for ASCII, astral Unicode, unpaired high/low surrogates, and embedded NUL. The existing `wtf8_bytes` uses `NativeStr` through the `CStr` alias in `thaw-runtime/src/lib.rs:29`, so registered lengths survive NUL. Add focused unrun controls for `new Error("first\u0002second\u0003third\u0004fourth\u0005fifth\u0006sixth")` with `.message`, `.cause`, `.code`, `.name`, `.stack`, `.toString`, `instanceof`, and own props; repeat with an explicit `cause` and QuickJS `code`/property bag to verify suffix parsing begins after the body. Include an Error subclass runtime name override, nested SuppressedError, QuickJS callback rejection round-trip, NAPI typed error, and legacy tagged literals. Assert Unicode unit lengths and evaluate message/cause getters once in their current order. Keep untagged thrown-string behavior and unrelated symbol/control-byte wire formats separate. No test/build/runtime execution until authorized by the root workflow.

The finding can close only after every dynamic structured-error producer and all named readers use the versioned body boundary. A runtime-only split or one HIR constructor change would leave QuickJS/NAPI and error metadata routes able to truncate user text.
