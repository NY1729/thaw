# Native Worker byte transport plan, HEAD495

Authority: managed HEAD `bfe64fc8e9d4af054c4d800e9b18241d613c4cb3`. Source planning only; no product edits, execution, tests, build, compiler, parser or formatter. Historical finding `01a0f1cb-dedb-7400-a660-9dcb13e42aa7:0` body read from ledger: native stdin/stdout/stderr String conversion loses invalid UTF8 Buffer bytes and default stdin data is incorrectly String. All three channels are required. Earlier plan491 is retained; this supersedes its availability assumptions with source evidence.

## Actual producer/ABI/consumer inventory

Parent stdin: registry builtins/system/workers.rs `startNativeWorker` creates WorkerWritable whose _write sends `String(chunk)` to `__thaw_worker_stdin`; final sends empty payload with ended=true. Context.rs1366 installs `(u32,String,bool)->bool` sender. processes.rs576 sends HostWorkerCommand::Stdin(String) or StdinEnd; run_host_worker command match at372/381 calls child `__thaw_host_worker_stdin(payload,false/true)`. Child bootstrap stdin listeners receive raw payload String at163–166; setEncoding only stores text at130 and does no decoding. EOF must remain a distinct command ordered after prior writes.

Child output: processes.rs136–139 overrides process.stdout/stderr.write with String(value) Host event enqueue. Captured console methods call those writers with formatted strings and newline; uncaptured console uses the existing host console path. drain_host_worker_events parses queue payload into HostWorkerEvent::Stdout/Stderr(String) at206–207. Poll outputs payload String at705/710. Registry worker platform poll pushes payload directly to _nativeStdout/_nativeStderr Readables. With capture true those are public worker.stdout/stderr; without capture they pipe into parent process.stdout/stderr via WorkerWritable that currently forwards String(chunk), creating another lossy boundary. Exit _finish ends the private/public output Readables. Thus preserving only captured output is incomplete.

Existing compatible byte transport: HostChild stdio uses byte Vec internally and hex strings at its poll boundary, with JS Buffer.from(value,'hex') consumers; HostStdin data similarly emits hex. `thaw-quickjs/lib.rs:467–485` provides existing hex codec. Worker can keep its existing String command/event ABI and carry hex payload, avoiding new Rust byte structures or variants. Update every Worker producer/consumer together; HostChild uses field value whereas Worker uses payload, so do not modify shared polling assumptions accidentally. Rust does not need to decode/re-encode Worker hex just to carry it through channels.

## Smallest complete implementation

Owners expected: registry `builtins/system/workers.rs`; QuickJS `quickjs/processes.rs`; registry `tests/platform.rs`. Existing Rust lib/context ABI remains a read dependency, unless stronger validation is required. No new dependency, decoder class or general transport abstraction.

1. Parent Worker stdin _write already receives normalized Buffer: stream core.rs39 converts string with requested/default encoding, and ArrayBufferView via `Buffer.from(chunk.buffer,chunk.byteOffset,chunk.byteLength)` before calling _write. Encode that Buffer directly with toString('hex'); do not String(chunk), double-encode strings, or discard the stream's encoding choice. Keep callbacks/errors/end ordering from existing Writable. Respect host send boolean: callback success only for accepted enqueue; rejected send must report existing stream-compatible error rather than silently claiming delivery. Final EOF similarly handles acceptance.
2. Child output writer accepts current public chunk contract string/Buffer/TypedArray/DataView, normalizes strings once with supplied encoding, and views with exact buffer/byteOffset/byteLength, then enqueues hex. Use existing Buffer codec. `Buffer.from(view)` in buffer_crypto.js38 uses element values for typed arrays, so explicitly use its ArrayBuffer overload for byte-range semantics; don't copy full backing buffers. Preserve write(value,encoding,callback) and write(value,callback), return behavior and callback once. Reject invalid chunks/encoding before enqueue. Avoid String(value) for binary chunks.
3. Registry poll decodes stdout/stderr payload via Buffer.from(payload,'hex') before Readable.push. Both captured and private default-output streams receive that same Buffer. Default pipe _write forwards the Buffer itself to parent process.stdout/stderr, preserving bytes and existing write callback/backpressure conventions. Text console uses the byte writer once; uncaptured console stays on its original path without duplicate events.
4. Child stdin delivery decodes hex to Buffer before dispatch. Without setEncoding, data listeners get Buffer. With encoding, use one persistent existing StringDecoder per stdin stream; `.write(buffer)` across chunks and `.end()` at EOF, emitting nonempty decoded tail before end. Preserve chunk order, skip decoder-empty intermediate strings, and emit end once. setEncoding must validate encoding when invoked, retain/flush prior decoder tail when switching coherently and not silently drop buffered incomplete bytes. Do not use per-chunk buffer.toString, which breaks split multibyte sequences.

## StringDecoder availability at the correct time

Bundled builtin implementation already exists in registry `builtins/streams/basic.rs:12–34`; it normalizes encoding and retains pending UTF8/UTF16/base64 bytes. Worker builtin currently explicitly requires node:stream only. Add a static `require('node:string_decoder')` dependency in the worker builtin so collection.rs136–158 recursively includes its factory and require edge. This changes bundle factory counts; update existing exact file_count assertions only after source inventory of which worker bundles gain the additional builtin.

Eval/native-file worker startup loads start.bundle_source before host_worker_bootstrap (processes.rs290–301), so the bundle_create_require global/factories are available then. Render.rs705 installs that global, and render.rs655–665 allows empty-base require to search bundled require maps. A static worker builtin decoder edge supplies resolution even if user source never imports it.

**Bundled data URL differs:** registry workers.rs selects an empty bundleSource for thaw-bundle URLs; bundle/workers.rs485 embeds resolver snapshot inside source, which runs *after* host_worker_bootstrap. Therefore unconditional `require('node:string_decoder')` during bootstrap is not safe. Bootstrap installs global require only at155, and that resolver can still be absent until embedded source executes. Resolve StringDecoder lazily on first setEncoding (or lazily in delivery once encoding selected), after normal worker source has installed its embedded resolver. Use `globalThis.__thaw_bundle_create_require('')('node:string_decoder')` or installed worker require, with an explicit availability check/error. For the supported registry-launched routes, bundle dependency inclusion plus source-before-input-dispatch ordering establishes availability by first user setEncoding. Do not claim availability for arbitrary raw host spawns with empty bundle and no resolver: that is a real dependency to expose or provide using existing builtin factory injection, not a reason to invent a duplicate decoder.

Existing StringDecoder may have independent UTF16 surrogate semantics limits; this unit should reuse it and report those honestly rather than create another divergent implementation. Standard UTF8 split/incomplete EOF must be covered.

## Unrun source controls

- Captured stdout and stderr emit bytes 00/ff/80 and valid UTF8; inspect Buffer hex and Buffer.isBuffer for default data. Include chunks arriving before listeners (Readable queued bytes), and exit flush/end order.
- Default-output path with captured parent sink verifies same hex as capture=true; intercept both parent stdout and stderr writes and preserve callback completion. Ensure stdout:false console output does not generate duplicate redirected events.
- Worker stdin receives Buffer by default with invalid UTF8 bytes unchanged; stdin.write string with explicit hex/latin1/utf8 encoding; stdin.end(finalChunk) sends final bytes before EOF; write/final callbacks exactly once and host rejection reports error.
- Subarray Uint8Array, typed view/DataView with nonzero offset and shorter byteLength for child output and parent stdin; no surrounding backing bytes leaked. Empty buffers preserve EOF distinction.
- Child stdin.setEncoding('utf8') combines a split multibyte character across at least two commands; incomplete EOF produces decoder tail before end. UTF16/base64 boundaries follow existing decoder; changing encoding flushes prior pending data consistently; invalid encoding fails at setEncoding.
- Eval worker, runtime file worker and bundled data URL worker all exercise setEncoding without importing decoder in user source. Source controls inspect static decoder dependency and lazy resolution order. Existing transfer/stdio/ref unit fixtures and expected bundle factory counts remain coherent; don't drop their features to make counts pass.

## Scope/dependencies

Preserve accepted native transfer staging/routing, shared validated move, child pending cleanup, stdio channel draining and ref/unref/exit ordering. Hex wire is an internal byte codec, not user-facing encoding. Full Stream pause/resume/backpressure semantics and standalone decoder edge cases are independent historical gates; byte transport must not assert those fixed. No source-only control establishes runtime behavior. If lazy resolver provenance for any launch route is missing, stop that dependent claim and supply the exact builtin edge/loader unit before accepting all three byte channels.
