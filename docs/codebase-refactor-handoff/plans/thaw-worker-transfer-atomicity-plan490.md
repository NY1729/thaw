# Sol source plan: Worker transfer atomicity

Authority HEAD 824a51f1505de81c60299c587bdeff59d0550bbe. No execution. Source-only planning; Luna must implement.

Confirmed source roots: registry workers.rs prepareNativePorts immediately calls __thawTransfer, rewires peers/queues, installs HostPortId and nativePorts mapping before encoding. Calls: native Worker.postMessage, startNativeWorker, decoded native port.postMessage. Child processes.rs __thaw_prepare_worker_ports does the same before parentPort/decoded-port encoding. Child direct and parent nativePostMessageToThread first structuredClone with transfer, then codec, so their transfers are already irreversible if subsequent codec fails. Builtin performance.js structuredClone itself moves a encountered port immediately, before later properties can throw. These paths share the late graph validation problem; fixing only registry order is insufficient.

Do not use recursive assertCloneable prewalk: it reads getters twice. Do not simply move encoder before prepare: codec requires HostPortId. Do not rollback peer pointers after arbitrary getter execution: reentrant getter may legitimately modify/close/send ports, and overwriting it loses user effects.

Preferred implementation: extend existing codec with optional transfer-port identifier resolver/map. Allocate ids in a local staging table, validate list types/duplicates/marks/closed and existing-id transfer semantics without moving endpoints or publishing maps; encode once using staged ids. After successful traversal, revalidate endpoints before commit since getters may close/transfer them. Only then transfer endpoints, bind/install mappings and detach buffers. Shared encoder preparation must serve parent and child callers. Existing sequence counters may advance on rejected encode; routing state must not publish. Preserve getter original exception identity and invocation count. Existing-id ports must follow explicit transfer eligibility rather than skipping detached validation. Check all transfer-list members even those absent from graph; transfer lists can contain disconnected-from-value members.

Builtin structuredClone: stage new port object shells during cloning, retain alias/cycle identity in seen, and delay peer/queue transfer until graph traversal and all source port validations succeed. Reuse MessagePort transfer logic with a staged destination if required; do not add an independent competing clone traversal. Detached port, duplicate, getter-side reentry and transfer-of-absent-port behavior must be specified and checked before source mutation. Parent/child direct messaging should encode the original value once using transfer staging, not structuredClone then codec with two independent transfer commits.

Before encoding, snapshot option/config conversions that can throw (String(source), JSON.stringify(config), options getters) without moving anything. Host send/spawn failure after encoding is a separate acceptance boundary: trace return values and existing Node-compatible semantics before promising rollback of already accepted transfers. Do not claim all transport failures atomic from encoding order alone.

Controls to add, unrun: graph with port first then throwing getter/function/marked object leaves original port connected and source buffer byteLength unchanged; no host send/spawn; same getter thrown object, one read; successful transfer queues/routes original data and disables source; second/duplicate/detached/marked transfer rejects before moving any sibling; getter closing/moving another staged port does not cause partial new transfers; cycles/aliases and Map/Set ports; transfer-only member; parent native, child parentPort, restored native port, direct-message and builtin structuredClone paths. Track broader external clone double-read gate separately.

Implementation should use smallest shared existing helper extension. Keep historical clone finding partial until external preexisting structuredClone guard and remaining transport contract are also addressed.
