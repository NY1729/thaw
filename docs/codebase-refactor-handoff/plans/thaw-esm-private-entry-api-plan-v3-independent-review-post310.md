# Independent source review: private native ESM entry plan v3

Reviewed `/tmp/thaw-esm-private-entry-api-plan-post309-v3.md` SHA-256 `f5bac7267a2c557a49f27c31d20c049eb2dea852c434c504a587f5d57885831e` against the v1/v2 plans and pinned rquickjs-core 0.12.2 source at HEAD310. Source-only; no product execution or managed edits.

Verdict: **ACCEPT design for a pure native ESM implementation candidate**, subject to full source review of that candidate. V3 addresses the three prior HOLD gates. The private owner stores no typed Module, so `Module<Declared>`/`Module<Evaluated>` cannot be confused. Capturing the namespace `Object` from the evaluated handle after `Module::eval` but before the eval Promise settles is consistent with `namespace()` returning an object without reading exported bindings (`value/module.rs:375-396,502-508`); any error rejects the already-published ready Promise. Every later callback/attachment error must likewise settle ready. The captured intrinsic Promise `then`, invoked with `This(eval_promise)`, avoids a user-replaced `Promise.prototype.then` silently bypassing attachment. The registry returns a bound Function capability, with no public eval-by-string token; a guessed monotonic sequence therefore cannot retrieve an old namespace. NUL module names are rejected before minting.

Ready is inserted before `declare`/`eval`, and all userdata/RefCell guards are dropped before engine calls. That handles synchronous reentry through the same bound Function while keeping evaluation once. `load_impl` remains the only pending-job driver. The planned controls for old absolute import, repeated bound call identity, synchronous self-reentry, and tampered Promise prototype directly cover the design's authority and liveness claims. The pure native route still publishes its chosen namespace intentionally; this acceptance makes no claim for CJS-first/mixed/Worker paths or the whole Task 12 finding.
