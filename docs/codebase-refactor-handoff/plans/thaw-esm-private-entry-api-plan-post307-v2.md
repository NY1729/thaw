# Private native ESM entry state correction (v2 supplement)

This supplements immutable v1 `/tmp/thaw-esm-private-entry-api-plan-post307.md` SHA-256 `ff24601c1fb343f9d727a04fd9aeb21f858159f5261e42ce29cd8a5f95b6db2d`. Base HEAD307; source-only, no product execution or managed edits.

The entry evaluator must publish an in-progress completion **before** calling `Module::eval`: eval can run module body synchronously and reenter the same host entry function. A map written only after eval would redeclare/evaluate the entry or return no Promise.

For a new token, create `(ready, resolve, reject) = Promise::new(&ctx)` (`rquickjs-core/value/promise.rs:82–84`), store `EntryState { ready: ready.clone(), phase: Starting }` under the key, then drop userdata/RefCell guards. A repeated call immediately returns the stored `ready` clone. Declare the source with its unique name, record the Module clone, and evaluate with no state borrow held. Loader registration and nested import resolution may reenter the owner. On successful eval, store `Module<Evaluated>`; attach fulfillment/rejection callbacks to its eval Promise using `eval_promise.then()?.call((This(eval_promise.clone()), on_ok, on_error))`, exactly the `This` call form used by pinned rquickjs's PromiseFuture (`value/promise.rs:205–215`). `on_ok` obtains the evaluated Module namespace and calls `resolve(namespace)`; `on_error` calls `reject(original_value)` without stringifying it. The callbacks capture owned Module and resolver/reject Function clones, not owner guards. The returned `ready` always represents completion after namespace selection. Future mixed support may replace `namespace` with the facade here, without changing the outward Promise ABI.

If declaration/eval raises `rquickjs::Error::Exception`, obtain `ctx.catch()` immediately (`context/ctx.rs:257–263`) and reject the stored bridge Promise with that actual JS value. Other Rust API errors may be converted to a JS Error/rejection, but must not leave `phase: Starting` permanently pending. If attaching callbacks fails, reject `ready` and retain its settled state. A repeated request returns the same rejected Promise. No `Promise::finish` or job draining occurs inside the host callback; existing `load_impl` drives `__thaw_module_ready` after the generated script finishes (`quickjs/api.rs:315–345`). The source registration function validates and mints its sequence before any JS engine call; `EntryState` only covers evaluation, not user-selectable prefixes.

This state machine is needed even for the pure ESM precursor. It does not authorize CJS-first synchronous require, mixed facade, or Worker paths, which have additional reentry/cycle contracts. An unrun regression should make an entry module call `__thaw_eval_native_entry` with its own token during evaluation (or an equivalent host callback), assert the returned Promise is the in-progress one, and verify side effects occur once. Because the token is scoped inside the rendered IIFE, the fixture must use a deliberately captured test hook rather than publishing the raw native namespace as a debug API.
