# Native QuickJS ESM mixed-graph implementation plan, source-only at HEAD e97c2d0353aa4769fad2d66657fd2ff890aebacd

Continuation of `/tmp/thaw-native-quickjs-esm-loader-source-design-post305.md`. No product code or tests/builds/parsers/JIT/runtime/network executed. This is a full-scope integration plan, **not** a claim that enabling the native loader alone closes the finding.

## Engine facts that constrain the plan

Pinned rquickjs 0.12.2 has `Module::declare`, `eval` and `namespace` (`rquickjs-core/src/value/module.rs:260-396,502-509`) and `Runtime::set_loader` behind its `loader` feature (`runtime/base.rs:98-108`, `rquickjs/Cargo.toml:58,111`). `relative-path` is already in Cargo.lock. The engine's `JS_EvalFunction` module branch creates module variables, links all dependencies, then evaluates (`rquickjs-sys/quickjs.c:37270-37285`); `JS_GetModuleNamespace` builds a live namespace from linked var refs (`:30405-30510`). Its dynamic import path resolves/links, evaluates, and resolves with that namespace (`:30975-31035`). This is precisely the native instantiation behavior the current script-factory pipeline lacks.

However, `Module::namespace` is not a magic JS-level synchronous `require(ESM)` bridge. It needs the same linked module record. The public `Loader::load` receives/returns a `Module` (`loader.rs:96-108`), but there is no current retained per-key module handle in thaw. `Module` is not visibly `Clone`; any retention must use supported `Persistent`/value ownership or carefully audited QuickJS raw refcounts, and namespace access before link must be forbidden. This is an implementation gate, not a verified solution.

## Owners and implementation order

1. **Source registration and loader:** `crates/thaw-quickjs/Cargo.toml` enables existing `rquickjs/loader`; `quickjs/context.rs:186-191` installs one resolver/loader per thread before any script. `quickjs/api.rs:315-337` keeps its `__thaw_module_ready` wait. `registry/bundle/collection.rs:552-579` preserves original source alongside current transformed source, keyed by existing package-instance key and import/requires maps. `registry/bundle/render.rs:224-280,390-400` emits registration data *before* any native import in parent and serialized Worker snapshots. Resolver maps `(canonical referrer, specifier)` through the exact existing `imports` map; retain query/fragment identity and separate require/import conditions, builtin names, private-package failures. Loader reads only registered plain data and returns `Module::declare` for ESM; it must not read arbitrary package getters or filesystem. Namespace and readiness for the ESM entry feed the existing `module.exports`/bridge path (`render.rs:499-507`, `bridge/generation.rs:771-781`). Gate: pure ESM cycle/TLA/diamond, two same-specifier package instances and alias query identity; no old JS factory for an ESM key may also run.

2. **Native synthetic modules for ESM -> CJS/builtin/JSON/addon:** `registry/bundle/collection.rs:519-565` already distinguishes resolved keys and `commonjs_context`; `render.rs:332-375` owns CJS execution and addon/builtin fallback. The loader must return one native module adapter per canonical opaque key, with an export list computed from the bundle's static ESM import/reexport requests before linking. Its *evaluation* calls the existing CJS factory/JSON/builtin/addon path exactly once and stores the result in the same bundle cache; default interop follows current `defaultImport` behavior (`render.rs:178-184`). Named imports require an explicit compatibility decision: current rewritten ESM references read `cjsValue[name]` live (`module_transform.rs:1232-1253` and live-import rewrite), whereas a simple generated `export const name = cjsValue.name` snapshots a primitive. If live named CJS bindings are required, adapter must update native export cells when the CJS backing property changes or otherwise retain the current live-access transform at that boundary. Do not silently regress it. `export *` from unknown opaque CJS/native names remains the separately open early-discovery contract; a static adapter cannot conjure unknown names during native linking without pre-running opaque code. Gate: CJS default/named mutation, explicit reexport, JSON, `node:` builtin, `.node` addon, side-effect once, and opaque-star declared expectation.

3. **CJS -> ESM synchronous `require`:** `render.rs:323-358` synchronously returns a cached partial/final `module.exports`; after native migration, it must return the *same* QuickJS native namespace for an ESM target, never execute the transformed ESM factory. For a linked ESM target in a mixed evaluation cycle, a host bridge may retrieve its namespace from the retained native record without evaluating it again; QuickJS's module link precedes evaluation (`quickjs.c:37270-37285`). For a CJS-first top-level `require(ESM)` outside an already linked graph, the bridge must compile/link and start native evaluation once, then return namespace only for synchronously completed ESM. A TLA ESM cannot be synchronously unwrapped: define an explicit error/unsupported contract rather than returning a pending Promise as `require` value. The pinned safe Module API does not itself expose a by-key synchronous JS lookup; design and source-audit retention/ownership first. Native module-name cache and JS CJS cache must point to one execution/namespace identity. Gate: CJS↔ESM cycle, partial namespace, sync function/var/let behavior, external CJS require ESM, TLA rejection, retry after throw, and no duplicate effects. If this bridge cannot be implemented without unsupported unsafe engine access, do not ship mixed native routing; reassess custom-cell path or a narrower declared compatibility contract.

4. **Worker:** `registry/bundle/workers.rs:433-460,480-487` currently serializes transformed Worker entry and origin snapshot; `thaw-quickjs/quickjs/processes.rs:241-255` loads bundle source, bootstrap, then executes Worker source as a script, and `context.rs:186-191` initializes a fresh runtime on that thread. Preserve that order but register original ESM sources in the child snapshot, then import the Worker entry natively *once* after bootstrap provides `parentPort`. Do not also run the old rewritten entry or create a second module cache. Keep saved A/B/nested URL affinity, filename/import.meta, `module.ready`/falsy thrown rejection, and existing CJS/eval Worker routes. Gates: cycle mid-read TDZ/function/var, one entry side effect/cache identity, native/fallback Worker, mixed CJS import, saved URL cross-bundle. Existing `platform.rs:947-1005,1025+` fixtures are narrower than these gates.

## Decision

Native QuickJS remains the first correctness path because its module linker already handles lexical TDZ/function hoisting and live ESM aliases. The smallest *full* integration is the loader/registration plus two-direction CJS bridge plus Worker adaptation above; pure ESM alone is a precursor only. The most consequential uncertain gate is synchronous `require(ESM)` from a mixed CJS cycle with one native namespace. Resolve the retained-module-handle and adapter live-named-export questions from pinned APIs before editing production. Do not substitute a second transformed ESM factory as a shortcut. If those gates prove infeasible in the current host API, record the exact blocker and compare a bounded custom-cell transform; do not claim that native import alone completes mixed semantics.
