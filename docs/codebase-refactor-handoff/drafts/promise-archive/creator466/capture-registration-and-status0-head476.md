# Source checkpoint (unrun, mutable)

Capture registration now has a checked `u8` ABI. `thaw_arena::try_register_reset_hook` reserves hook capacity before the runtime capture-cell ledger reserves its own slot. Only after both succeed does LLVM update the new cell, untrack the source, and zero its creator ticket. The failure branch leaves the source ticket untouched and raises a synthetic typed error. For a loop preheader the old unconditional edge is replaced by a checked success tail; the recorded loop promotion scope is moved to that tail so a later promotion is inserted after the first check. Empty Promise capture cells use the same status check. The source and IR controls were edited but not executed.

The split-async rejection fallback now transfers the currently delivered subscription's existing source share into the completion. `thaw_runtime_poll_one` exposes only its stack-local delivered subscription through a thread-local pointer for the duration of `resume`; nested polls restore the previous pointer. The new helper validates live source/output, rejected settled source, and pending output before changing the subscription. It copies exact typed fields and native text metadata, sets `subscription.source = null` before publishing the completion, and returns status 1. The completion's result-kind is explicitly borrowed (`0`), since final release must retire the result through `rejection_source`; copying a tag-7 source's owned result-kind would destroy the same Box twice. On status 0 the subscription retains its source for normal Drop. The prior extra-retain fallback remains available but is no longer used by this generated resume. A direct unrun ownership control was added.

Whole-candidate HOLD remains. The generated resume currently ignores the new helper's status on a contract violation, so source-invalid or delivery-mismatch reentry needs explicit disposition proof; completion-already-settled is now a successful no-op that leaves subscription ownership unchanged. Native-only non-HTTP deferred cleanup still lacks an exact terminal reporter: `entrypoints.rs` registers the generated JSON driver only for QuickJS handles or `createServer`, and Lambda only for QuickJS handles, while `std/json.rs::thaw_json_run_deferred_cleanup_turn` declines to process packets without a driver. The existing generated driver calls `thaw_js_emit_uncaught_graph_result` and `thaw_js_report_terminal_handle`, so simply registering it in a native-only module would introduce an unsupported JS dependency. This checkpoint claims neither product behavior nor compilation.
