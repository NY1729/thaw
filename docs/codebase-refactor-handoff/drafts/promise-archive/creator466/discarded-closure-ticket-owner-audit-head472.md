# Discarded Promise capture ticket: source authority audit

Status: source audit that preceded the mutable capture-cell ledger. The later implementation and its remaining gates are recorded in `checkpoint-discarded-closure-cells-head472.md`. No product execution.

* `values/closures.rs::allocate_lambda_environment` first calls `promote_variable_to_arena_cell` for every capture. For Promise captures, promotion copies the compiler ticket into an arena `i64` cell and zeros the old cell (`:116–130`), then the closure stores a pointer to that same ticket cell (`:241–260`). A subsequent closure invocation loads the pointer (`:1104–1117`). Thus the ticket is a shared mutable cell, not a closure-owned copy: dropping one closure must not destroy a creator still referenced by another closure or the outer variable.
* `functions.rs::store_promise_creator_cell_ticket` updates that cell on assignment. `clear_promise_creator_ticket_source` zeros it on Return/direct await; the closure expression-return path invokes this helper (`values/closures.rs:1154–1160`). A closure never invoked and an outer scope that exits without moving the ticket leave a nonzero ticket in the arena cell.
* Write-site inventory for any tracked-cell ABI: `values/closures.rs:127–130` promotes/copies and zeros the source; `:248–251` creates an initially zero capture cell; `functions.rs:287` replaces a ticket and `:322` clears a moved source; `statements.rs:266`, `async_frames/codegen.rs:916`, and `values/closures.rs:1157` all call the shared clear helper. Async-frame header/local ticket stores (`async_frames/codegen.rs:245,1133`) are separate frame-owned slots and must not be double-registered as capture cells. A tracking call only after promotion is too late on its OOM edge: the old source has already been zeroed, so the tracking reserve must precede that transfer and preserve the preheader's branch structure.
* Native `ArenaRoot` only pins an arena pointer and removes that pin on Drop (`thaw-arena/src/lib.rs:34–61`); it does not run a closure-specific finalizer. QuickJS native callback wrappers hold `ArenaRoot::new(closure)` (`thaw-quickjs/src/quickjs/api.rs:2332`), proving wrapper reachability, not creator retirement. Direct native closure aliases have no JS-wrapper Drop at all.
* Arena reset computes live allocations from registered roots and pins and exposes `was_reclaimed` to reset hooks only after reclaim (`thaw-arena/src/lib.rs:193–277`). Reading the ticket cell in that hook would be UAF. The existing `std/json.rs::reset_arena_owned_json_roots` pattern stores a side-table owner identity and token before reset and tests token reclamation afterward (`:1085–1164`). A creator-ticket analogue must side-track each arena ticket cell's latest ticket identity on promotion/assignment/move, then retire only when its token is reclaimed; registering one finalizer per closure would double-release a shared cell.
* A direct call to `thaw_promise_destroy_creator_ticket` from a reset hook is not yet safe: last release can drop Host/Json payloads and reenter generated code after arena reclamation, while exact pending-tuple snapshot/packet ownership is unavailable there. The next coherent source change is a side-table plus a separately rooted deferred ticket-retirement queue, consumed by a generated exact cleanup driver at a safe event/invocation boundary. Tracking must be committed before source-cell zeroing and be updated by **all** ticket-cell writes, including promotion, replacement, Return/await move and callback capture. Queue insertion at reset must not dereference reclaimed cells or allocate after the last owner is removed; reserve its node when the ticket is acquired.

This distinguishes the source-proven authority from a tempting but incorrect closure-Drop release. The successor now has a side-table and a generated C-main deferred-ticket consumer, but lacks a guaranteed C-main sweep and Lambda/native-only exact boundary; discarded closure creators remain a full-scope HOLD.
