Status: **HOLD**. No build, test, or product execution; no managed checkout edits.

`values/closures.rs` registers the promoted arena ticket cell before zeroing its source and registers a newly created zero capture cell. The shared ticket store/move helper updates only registered capture cells, leaving stack and async-frame slots on their existing paths. Runtime keeps `(cell address, latest ticket, deferred bit)` in a thread-local side table. Its arena reset hook uses `thaw_arena::was_reclaimed` after reset and never dereferences the freed cell or calls a destructor. Unrun controls distinguish a pinned closure, an unpinned cell, and a moved ticket.

The generated QuickJS/HTTP C-main terminal turn checks the deferred identity queue, reserves an exact snapshot, Json cleanup token and reentry packet **before** taking a ticket, and invokes `thaw_promise_destroy_creator_ticket` with pending channels isolated. Reentry is queued and the original tuple restored. Allocation failure before take leaves the runtime identity queued. The existing bounded Json packet turn then processes any reentrant report.

This is not a full lifetime fix. Ordinary C-main currently has no explicit arena reset, so a discarded local capture cell need not be marked deferred before process exit. Lambda resets at each invocation but lacks the generated driver registration and post-reset exact turn. Native-only non-HTTP modules have no QuickJS exact terminal emitter. Side-table `Vec::push` uses the existing Rust allocator rather than an explicit status/OOM rollback contract. The full exact reporter, status0 void completion, producer tickets beyond current typed lanes, and closure alias ownership still require whole-source review.
